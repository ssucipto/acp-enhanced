# Audit Report: feedback-007 — /acp-integrity Command Suitability Analysis

**Audit**: #053  
**Date**: 2026-06-07  
**Subject**: Critical review of feedback-007 v2.0 proposing `/acp-integrity` + `/acp-rule-file-audit` commands — 70 rules, 11 categories, 3 companion files  

## Summary

Feedback-007 proposes a 70-rule `/acp-integrity` command for detecting malicious code, prompt injection, memory poisoning, and supply chain threats. The proposal is exceptionally well-researched with real 2025–2026 threat references (Pillar Security, CrowdStrike, OWASP LLM Top 10, Mini Shai-Hulud worm). However, it has **4 critical gaps** that make the full proposal unsuitable for implementation as-is: the agent self-protection paradox, missing script infrastructure, a fundamental mismatch with ACP's LLM-dispatch architecture, and bundled scope creep.

**Recommendation**: ACCEPT with major scope reduction. Ship a lightweight v1.0 focusing on pattern-matching rules (Unicode scanning, AI-directive phrases, ACP rule file integrity). Defer semantic analysis (taint flow, memory poisoning) to v2.0 when supporting script tooling exists. Split the recurring tasks system into its own milestone.

## Key Findings

### CRITICAL GAPS (block implementation as-designed)

| ID | Severity | Finding | Impact |
|----|----------|---------|--------|
| **GAP-053-01** | **CRITICAL** | **Agent Self-Protection Paradox** — IG-51 through IG-57 ask an LLM agent to detect prompt injection targeting itself. An LLM cannot reliably detect adversarial content designed to manipulate LLMs. The HALT instruction assumes the agent will recognize injection *before* being influenced by it — this is the exact vulnerability the rules claim to detect. Real-world: Anthropic's own MCP server had 3 prompt injection CVEs (CVE-2025-68143/44/45) — if Anthropic can't prevent injection in their own tools, an ACP command doc cannot make an agent immune. | Rules IG-51–IG-57 produce unreliable results. False negatives are guaranteed. False positives cause alert fatigue. |
| **GAP-053-02** | **CRITICAL** | **Missing Script Infrastructure** — At least 4 bash scripts are required but none are drafted: (1) Unicode scanner for IG-14–IG-16, (2) Shannon entropy calculator for IG-17, (3) manifest SHA-256 hash generator for `--diff`, (4) network whitelist validator for IG-01. LLMs cannot do byte-level scanning — these MUST be bash scripts. Without them, the LLM is being asked to perform analysis it physically cannot do. | Core rules (IG-14–IG-20, IG-38–IG-39) cannot execute. The command is non-functional without scripts. |
| **GAP-053-03** | **HIGH** | **ACP Architecture Mismatch** — ACP Enhanced is an LLM-dispatch framework (bash scripts + YAML + command docs that tell LLMs what to reason about). It is NOT a SAST tool. Many proposed rules are static analysis tasks: Unicode byte scanning (IG-14–IG-16), entropy calculation (IG-17), dependency tree diffing (IG-29–IG-31), commit provenance (IG-33–IG-37). These should be done by deterministic tools, not LLM reasoning. LLMs add latency, cost, and non-determinism to tasks that `grep`, `sort`, and `diff` do better. | Expensive LLM tokens spent on grep-level tasks. False positives from LLM hallucination on objective pattern matching. |
| **GAP-053-04** | **HIGH** | **Bundled Scope Creep** — The proposal bundles 4 separate features: (1) the integrity command itself, (2) a recurring tasks scheduler (§4.2–4.3, progress.yaml schema extension, AGENTS.md Step 4.5), (3) pre-commit hooks in constraints.yml (§5.2), and (4) schema changes to identity.yml (team_members field). These are independent concerns. The recurring tasks system alone is a full milestone. | Bloated milestone. The integrity command should ship standalone; recurring tasks and pre-commit hooks are separate features. |

### INCONSISTENCIES (contradictions within the proposal)

| ID | Severity | Finding | Fix |
|----|----------|---------|-----|
| **INC-053-01** | MEDIUM | **Rule Count Mismatch** — Claims "70 rules across 10 categories" but lists 11 categories (1–10 + GitHub Actions at §11). Category 11 contains IG-63–IG-70 (8 rules). Actual count: 70 rules, 11 categories. | Rename to "11 categories" or merge Category 11 into 9/6. |
| **INC-053-02** | MEDIUM | **Executor Conflict for --origin deepseek** — V4 Pro is "disqualified for --origin deepseek scans" but "eligible for --phase1 only." If code was generated by DeepSeek AND we want Phase 1, which executor runs? The constraints are contradictory. | Clarify: "If --origin deepseek, ALL phases require non-DeepSeek executor. Phase 1 cost-efficient path is unavailable for DeepSeek-origin code." |
| **INC-053-03** | LOW | **Redundant Sub-command** — `/acp-rule-file-audit` is a strict subset of `/acp-integrity --self`. It adds a separate command doc, separate taxonomy entry, and separate invocation for what is essentially a flag combination. No distinct value beyond shorter invocation. | Merge into `/acp-integrity --self --fast` or keep as alias. Don't create separate taxonomy types. |
| **INC-053-04** | MEDIUM | **IG-63 Mis-categorized** — IG-63 (multi-language injection evasion via Mandarin/Arabic/Portuguese fragments) is listed under Category 11 (GitHub Actions) but is a prompt injection evasion technique — belongs in Category 9 (Prompt Injection Surface). | Move IG-63 to Category 9. |
| **INC-053-05** | LOW | **network_whitelist.yml Not Defined** — IG-01 requires `agent/core/network_whitelist.yml` but no schema, bootstrap integration, or validation is specified beyond a 5-line stub. The file would need its own E2E test and validate check. | Add to the bootstrap step plan with full schema definition. |

### SUITABILITY — What Doesn't Work

| Aspect | Assessment |
|--------|-----------|
| **LLM self-protection (IG-51–57)** | Fundamentally unreliable — see GAP-053-01 |
| **Byte-level analysis via LLM** | Architecturally wrong — needs bash scripts, not LLM reasoning (GAP-053-02, GAP-053-03) |
| **Taint flow analysis (IG-45–50)** | LLMs can reason about data flow but not with SAST accuracy. Acceptable as "best-effort" with `confidence: MEDIUM` default, not `HIGH`. |
| **Memory poisoning detection (IG-58–62)** | Semantic contradiction detection is LLM-capable but unreliable. 60–89% AUR in research papers means 11–40% false negative rate. Document this limitation. |
| **70-rule scope for v1** | Too large. feedback-006 (acp-review) shipped 54 rules and was the largest command doc to date. 70 rules with 4 new scripts, 3 new YAML files, and a schema change is 2–3× the complexity. |

## Recommendations

### 1. ACCEPT with Major Scope Reduction — Two-Phase Shipment

**v1.0 (M56 — achievable in 1 milestone, ~8 routes, ~10h)**:

| Deliverable | Scope |
|-------------|-------|
| `agent/commands/acp.integrity.md` | Pattern-matching rules ONLY: Categories 1–7, 11 (IG-01–IG-44, IG-63–IG-70). No taint flow. No memory scan. No prompt injection self-detection. |
| `agent/scripts/acp.unicode-scan.sh` | Hidden Unicode scanner (U+200B, U+200C, U+200D, U+FEFF, U+202A–U+202E, U+2066–U+2069) — bash + Python fallback |
| `agent/scripts/acp.entropy-scan.sh` | Shannon entropy calculator for IG-17 |
| `agent/core/network_whitelist.yml` | Bootstrap-created stub with schema |
| `agent/skills/code-integrity.md` | ≤500 tokens, Phase 1 only, copilot executor |
| `agent/routing/taxonomy.yml` | 2 task types: `code-integrity-scan`, `rule-file-audit` |
| `e2e/acp.integrity.test.sh` | 10+ assertions (structural + Unicode fixture) |
| Version bump | 6.11.0 → 6.12.0 (minor — new command) |

**Explicitly DEFERRED to v2.0**:
- Categories 8 (Taint Flow — IG-45–IG-50) → needs SAST-grade analysis
- Categories 9 (Prompt Injection Surface — IG-51–IG-57) → LLM self-protection paradox unresolved
- Categories 10 (Memory Integrity — IG-58–IG-62) → needs semantic contradiction research
- Recurring tasks system (§4.2–4.3) → separate milestone
- Pre-commit hooks in constraints.yml (§5.2) → separate milestone

### 2. Merge `/acp-rule-file-audit` into `/acp-integrity`

Replace the separate command with a `--fast` flag: `/acp-integrity --fast` = rule files only, Phase 1, V4 Pro eligible. One command doc, one taxonomy entry, one skill file.

### 3. Fix the Agent Self-Protection Language

Replace IG-51–IG-57's "HALT and detect injection" with honest scoping:
> ⚠️ **Limitation**: An LLM agent cannot reliably detect prompt injection targeting itself. These rules flag *known injection patterns* (directive phrases, HTML comment instructions) as suspicious for **human review**. The agent does NOT self-halt — it flags and continues. False negatives are expected. This is a best-effort screening tool, not a security boundary.

### 4. Split Recurring Tasks into M57

The recurring tasks scheduler (§4.2–4.3), pre-commit hooks (§5.2), and `progress.yaml` schema extension are a separate feature. Ship M56 (integrity v1.0) first, then M57 (scheduled reviews).

### 5. Add Scripts BEFORE Command Doc

Unlike `/acp-review` (pure LLM reasoning), `/acp-integrity` depends on bash scripts for core functionality. Build scripts FIRST, then wrap with command doc. This is the reverse of the normal ACP pattern but necessary here.

## Readiness Verdict

**CONDITIONALLY READY** — The concept is strong and the research is solid, but the proposal must be scoped down to what ACP's architecture can actually deliver. Ship v1.0 as pattern-matching integrity scan with supporting bash scripts. Defer semantic/taint/memory analysis to v2.0. Split recurring tasks into its own milestone.

**If accepted as-is (full 70 rules)**: BLOCKED by GAP-053-01 (self-protection paradox), GAP-053-02 (missing scripts), and GAP-053-04 (scope creep).

**If accepted with scope reduction (v1.0 = ~40 rules, Categories 1–7 + 11)**: READY for planning. Estimate 1 milestone, ~8 routes, ~10 hours.
