# Milestone 28: opencode Command Parity

**Goal**: Every `/acp-*` command available in GitHub Copilot is equally available in opencode (and any tool using `.opencode/commands/`), so both environments have identical capabilities.  
**Duration**: ~1 week  
**Dependencies**: None — can run concurrently with M25  
**Status**: completed  
**ADR**: ADR-6 — Cross-tool slash command parity via per-tool command directories

---

## Overview

GitHub Copilot users invoke ACP commands via `/acp-*` slash commands powered by `.github/prompts/acp-*.prompt.md`. opencode users have no equivalent — there is no `.opencode/commands/` directory, so:

1. `/acp-*` commands fail in opencode (command not found)
2. The `@acp.<command>` notation is broken — `@` in opencode is a file-reference syntax, not command invocation
3. Users fall back to manually telling the agent to "read agent/commands/acp.init.md" which is fragile

The fix is to create `.opencode/commands/acp-*.md` files that mirror the `.github/prompts/` directory. After M28, typing `/acp-init` in opencode will read `.opencode/commands/acp-init.md` → delegate to `agent/commands/acp.init.md` — identical to Copilot.

**Architecture Decision (ADR-6)**: `.github/prompts/` is the canonical source. `.opencode/commands/` is a derived artifact, generated by `acp-bootstrap.sh` at install time and committed to the repo so project clones get opencode support without re-running bootstrap.

- [ ] `.opencode/commands/` also contains `git-commit.md` and `git-init.md`

- [ ] opencode command files DO contain `description:` matching the Copilot prompt description
- [ ] `acp-bootstrap.sh` generates `.opencode/commands/` during fresh installs
- [ ] `acp.install.sh` creates the `.opencode/commands/` directory
- [ ] AGENT.md invocation table includes opencode row
- [ ] E2E test `acp.opencode-commands.test.sh` enforces 1:1 parity with no silent drift
