## 1. Problem Statement

During `/acp-visualize` on FIFOZ, the **Patterns** page showed **"No patterns recorded yet"** despite
36 entries in `agent/memory/patterns.md`, and the **Sessions** page showed the same empty state despite
13 entries in `agent/memory/sessions.md`. Investigation revealed **shared failure modes** across the
memory layer:
(a) malformed YAML in project registries, (b) **`/acp-commit` does not auto-sync** registry entries to document directories
(`agent/patterns/*.md`, `agent/sessions/*.md`), (c) visualizer parser fragility that fails silently,
and (d) schema drift between `/acp-commit` field names and visualizer types. Similar YAML issues affected
`agent/progress.yaml` (unquoted colons in `notes:` values).

---

## 2. Root Cause Analysis

### 2.1 Not an auto-generation bug — dual-store design gap (ACP Enhanced)

ACP Enhanced maintains **two pattern stores** with no documented sync:

| Store | Purpose | Populated by |
|-------|---------|--------------|
| `agent/memory/patterns.md` | Session registry (YAML list) | `/acp-commit` step 3 |
| `agent/patterns/*.md` | Full pattern documents | **Must be auto-generated by `/acp-commit` step 3b (v6.9)** — today: `/acp-pattern-create` one-at-a-time or manual |

FIFOZ accumulated 36 registry entries over months of `/acp-commit` and audits, but
`agent/patterns/` contained only templates (`.gitkeep`, `pattern.template.md`). Commands
like `/acp-init`, `/acp-plan`, and `/acp-proceed` read **`agent/patterns/`**, not the registry.
This is a **protocol gap**, not a code crash: agents follow `/acp-commit` (writes registry only;
**does not** generate `agent/patterns/*.md` — that must happen automatically in v6.9).

### 2.2 Malformed registry YAML — agent + missing validation (ACP Enhanced)

`agent/memory/patterns.md` line 120 had `native-kdf-wrapper` missing `- date:` list marker.
js-yaml (used by visualizer) rejected the entire file with `duplicated mapping key`.
Ruby/libyaml parsed leniently but **silently merged** `ocr-llm-provider-pattern` into the
previous entry — data loss without error.

`/acp-validate` Step 6 validates **`agent/patterns/*.md` structure** but does **not** validate
`agent/memory/patterns.md` or `agent/progress.yaml` YAML syntax. Invalid registry YAML is
only caught at visualizer runtime (or manual inspection).

### 2.4 Sessions registry — same dual-store + validation gap (ACP Enhanced)

ACP Enhanced maintains **session memory** in `agent/memory/sessions.md` (YAML list written by
`/acp-commit`) but the visualizer and future `/acp-init` reads expect parseable structured data.
FIFOZ had **13 session entries + 4 weekly summaries** in the registry but **zero files** in
`agent/sessions/` until manual remediation (2026-06-03).

| Store | Purpose | Populated by |
|-------|---------|--------------|
| `agent/memory/sessions.md` | Session registry (YAML list) | `/acp-commit` step 2 |
| `agent/sessions/*.md` | Full session documents | **Must be auto-generated by `/acp-commit` step 2b (v6.9)** — today: manual/scripted only |

**YAML defect**: weekly-summary `key_facts` entries with unquoted colons (e.g. `Hermes: @noble/...`,
`M_KDF: react-native-quick-crypto...`) caused js-yaml to reject the **entire** sessions.md file.
Visualizer returned 0 entries → "No sessions recorded yet."

**Schema drift** (Visualizer): `SessionEntry` expects `tasks_completed: string[]` but `/acp-commit`
writes `tasks:`. Even after YAML fix, UI would show **"0 tasks"** per session. Weekly-summary blocks
use `week:` + `type: weekly-summary` instead of `date:` — not handled in timeline component.

### 2.5 Visualizer silent failure (Visualizer repo — not ACP Enhanced core)

`server/routes/api/memory-files.ts` → `parseYamlBlocks()`:
- On parse failure, returns `[]` with no error field
- UI shows "No patterns recorded yet" — indistinguishable from genuinely empty project
- v1.5.1 improved YAML error UX for `progress.yaml` but not for memory file fetches

### 2.6 Visualizer dev-mode instability (Visualizer repo)

React 19 SSR + TanStack Devtools caused `Internal React error: Expected static flag was missing`.
Vite SSR console forwarding created an exponential `[Server][Client]...` log echo loop (~900 KB
terminal output in 4 minutes, process exit 134). v1.5.1 changelog claims ClientOnly fix; still
observed on first-load dependency optimization reload.

## 3. Proposed Fix

### Primary requirement (ACP Enhanced)

**`/acp-commit` must automatically sync markdown documents from registries on every successful commit (default ON).** This is the fix for F-01 and F-01b — not optional standalone commands.

| Step | Action |
|------|--------|
| 2 | Write `agent/memory/sessions.md` (existing) |
| **2b** | **Auto-sync `agent/sessions/{date}-{slug}.md` for new/changed entries** |
| 3 | Append `agent/memory/patterns.md` if applicable (existing) |
| **3b** | **Auto-sync `agent/patterns/{name}.md` for new/changed entries** |
| 6 | Compact sessions if >15 entries (existing) |
| **6b** | **Re-sync session documents after compaction** |
| 7 | Confirm with sync counts |

- **`/acp-commit --no-sync`**: opt-out for debugging only; must warn that document dirs may drift.
- **`/acp-pattern-sync` / `/acp-session-sync`**: secondary repair tools (`--dry-run`, `--all`); same engine as steps 2b/3b; **not** the primary workflow.

### For ACP Enhanced (framework)

| ID | Fix | Priority |
|----|-----|----------|
| F-01 | **Extend `/acp-commit` step 3b**: auto-generate/update `agent/patterns/{name}.md` from registry after every commit (default ON) | High |
| F-01b | **Extend `/acp-commit` step 2b (+ 6b after compaction)**: auto-generate/update `agent/sessions/{date}-{slug}.md` from registry after every commit (default ON) | High |
| F-01c | Expose same sync engine as `/acp-pattern-sync` and `/acp-session-sync` for manual repair only | Medium |
| F-02 | Extend `/acp-validate`: YAML-parse `agent/memory/patterns.md`, `agent/memory/sessions.md`, `agent/progress.yaml`; fail on syntax errors with line numbers | High |
| F-03 | Document dual-store model in wiki: registry vs documents for **patterns and sessions**, when to use each, sync workflow | Medium |
| F-04 | Enforce `write_patterns_at_discovery` from constraints.yml — `/acp-commit` should prompt when `key_fact` looks like a reusable pattern | Medium |
| F-05 | Registry schema lint: require `- date:` and `name:` on every list item; warn on unquoted colons in scalar values | Medium |
| F-06 | `/acp-version-update` guard: warn before overwriting project-specific files in `agent/core/` (identity.yml, domain.yml, taxonomy.yml) | Medium |
| F-07 | `/acp-commit` YAML write hints: quote `key_facts` / `key_fact` scalars containing `:` (especially weekly-summary compaction) | Medium |

### For ACP Visualizer (separate repo)

| ID | Fix | Priority |
|----|-----|----------|
| V-01 | Return `{ entries, error }` from `fetchPatterns`/`fetchLessons`/`fetchSessions` on YAML parse failure; show ErrorCard (like progress.yaml) | High |
| V-02 | Harden `parseYamlBlocks`: prefer single-document YAML array parse first; surface js-yaml exception message | High |
| V-03 | Fix `SessionEntry` schema: read `tasks` (commit format) not only `tasks_completed`; support `type: weekly-summary` blocks | High |
| V-04 | Complete React 19 SSR devtools fix or disable devtools in dev by default | Medium |
| V-05 | Break Vite console.error echo loop (filter recursive `[Server][Client]` forwarding) | Medium |

## 5. Recommendation

**Yes — report to both teams**, split by repo:

1. **ACP Enhanced** (this file via `/acp-feedback`): F-01 through F-01c, F-02 through F-07 — **commit-integrated sync is P0**; standalone sync commands are repair-only
2. **Visualizer** (GitHub issue on `agent-context-protocol-visualizer`): V-01 through V-04

This is **not a single monolithic bug**. The empty Patterns and Sessions pages were a **chain**:
missing document directories (gap) + broken registry YAML (validation gap) + silent visualizer parse
(visualizer bug) + sessions schema drift (`tasks` vs `tasks_completed`).

**Severity rationale**: Medium — no data loss in git (registry recoverable), but agents and dashboard
misled for months; silent parse failure hides real content.
